## 1. Inputs the report is built from
- `--logs <logs.json>`  (log analyzer --json-out: timeline, iocs, coverage, chains, checkers)
- `--resp <triage.json>` (responder triage --json: findings incl. techniques, remediation status) — optional
- `--answers <answers.yaml>` (manual/meta fields the operator fills) — optional; if a field is missing, the CLI/bot/web ASKS for it.
- `--lang uz|ru|en` (default uz), `--out report.html`, `--md out.md`, `--docx out.docx` (docx only if python-docx available; otherwise print a note "python-docx yo'q — HTML'ni PDF'ga chop eting").

answers.yaml fields (all optional; asked if missing): title, org, date, team, analyst, exec_summary (free text; if empty AUTO-generate a factual one — see below), scope, recommendations (free text; may be empty).

## 2. model.py — assemble ReportModel (no AI)
`build(logs=None, resp=None, answers=None) -> dict` with sections:
- meta: title/org/date/team/analyst (from answers; date defaults today).
- exec_summary: use answers.exec_summary if given; ELSE auto-build a FACTUAL summary string from the data (template, not AI): e.g. "Tergov <N> hodisa, <H> host, <T> ATT&CK texnikasi aniqladi. Boshlang'ich kirish: <first-tactic technique>. Ta'sir: <impact techniques>. <K> IOC ajratildi. <R> remediation amali bajarildi." Fill counts from logs/resp.
- timeline: key events (from logs.timeline) — prefer high/medium-confidence events; each: ts, host, user, technique(s), short command. Cap to a readable number (e.g. top 40) with a note if truncated.
- techniques: DISTINCT techniques observed (from logs + resp), each {id, name, tactic, count, evidence-sample}. This is the ATT&CK answer table. Mark each active (already active from KB; do not include revoked). Sort by kill-chain tactic order.
- iocs: from logs.iocs (type/value/count/first/last), meaningful only (drop noise, same filtering spirit).
- hosts: affected hosts with their kill-chain tactics.
- coverage: tactics covered vs missing.
- remediation: from resp findings — item, technique, status (if resp has one) or "buyruq tayyorlandi", and whether protected. Split into "bajarildi/tayyor" and "qo'lda tekshirilsin" (unmatched_log_artifacts).
- checker_note: if logs.checkers present, a line "Davriy trafik (checker/SLA) aniqlandi — remediation'da tegilmadi".

## 3. render.py
- `render_html(model, lang) -> str`: SELF-CONTAINED offline HTML (inline CSS, no CDN), print-friendly (A4), sectioned, tables styled, headings from strings.yaml[lang]. Escape all data.
- `render_markdown(model, lang) -> str`.
- `render_docx(model, lang, path)`: only if `import docx` works; build a clean docx (title, headings, tables). If python-docx missing, raise a clear handled message the CLI turns into the "print HTML" note.
- strings.yaml: every section heading + column label in uz/ru/en. Technique names/IOCs are data (not translated). Keys e.g. title, exec_summary, timeline, techniques, iocs, hosts, remediation, recommendations, tactic, evidence, status, missing, done, manual_check, etc.

## 4. CLI (bk.py `report`)
`bk report [--logs logs.json] [--resp triage.json] [--answers a.yaml] [--lang uz] [--out report.html] [--md r.md] [--docx r.docx] [--ask]`
- With `--ask` (default when stdin is a TTY and required meta missing): interactively prompt for missing meta fields (title/org/date/team/analyst) in the chosen language; exec_summary/recommendations optional (blank => auto/omit).
- Non-interactive: use answers.yaml + defaults; never block.
- Always write HTML; also md/docx if requested. Print where files were written.

## 5. Web "Report" tab (bluekit/web)
